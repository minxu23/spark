Summit2MD

给一个 YouTube 峰会播放列表链接，或 Substack 播客链接，自动整理出全部议题链接、清洗后的文字记录，并生成逐议题小结与大会总结。

1获取议题列表

Substack 播客站点（包括自定义域名）支持单集页面、归档页（/archive）或标签页（比如 /t/podcast），会直接抓取节目自带的完整对话转写，不需要语音识别。
RSS/Atom 订阅源和 Apple Podcast（自动换成其背后的 RSS）会抓取每条的正文/节目简介；没有公开文字稿的单集会被跳过，不做语音识别。
微信公众号只支持逐篇粘贴具体文章链接（不支持按公众号名批量订阅）。

2选择议题

影响生成的总结怎么写：峰会总结会分析议程结构、策展思路；栏目总结只按内容本身归纳话题，不会编造"隶属于哪个内容矩阵"之类的背景。已根据链接类型自动选择，可以手动改。

默认按 YouTube 播放列表原始顺序排列，通常和实际议程顺序不一致；填这个链接可以尝试按会议官网的议程顺序重排，文件名编号也会跟着改用议程顺序（未匹配到的议题排在最后）。

3生成内容

只影响大会/节目总结这一次综合调用；不影响上面「为每个议题生成小结」——新处理的议题仍会正常生成小结。
什么时候需要"标注发言人"？
单人演讲会直接从标题解析出发言人，不需要这个选项；这个选项只对 Panel / Fireside Chat / Workshop / Startup Spotlight 这类多人对话生效，基于上下文推测（不下载音频），且同样需要下面的 AI 后端配置。
演讲稿和议题小结有什么区别？
speech 是主要输出目录：议题小结会和演讲稿放在同一篇文档里；transcripts 目录仍保留原始带时间戳的文字记录作为核对依据。单人演讲输出为连贯文章，多人对话会保留发言人分段。单次调用比只生成小结更耗时、更耗 token，超长内容可能被截断。
原字幕如果本身就是中文，选"中英文对照"会自动按中文处理（没有另一种语言可对照）。
高级：输出目录、字幕语言与小结篇幅
"小结生成范围"（选哪几个议题生成小结）在上面议题表格的工具栏里设置。

4AI 后端与成本

每家给了 1 个旗舰模型 + 1 个性价比模型，带 ~xxx-latest 的会自动跟随 该系列在 OpenRouter 上的最新版本，不用跟着改；没有 latest 别名的就固定了一个具体版本号， 以后可能过期，到时候手动换新的即可。也可以直接手动输入别的 OpenRouter 模型 id。
高级：自定义 API Base URL（可选）
使用 OpenAI Chat Completions 兼容协议。可填写到 /v1，工具会自动补上 /chat/completions；也可直接填写完整接口地址。Key 仅用于当前任务，不写入文件或浏览器存储。
需要本机（或局域网内）已启动 Ollama 服务，且模型已通过 ollama pull <模型> 拉取到本地。无需 API Key。
需要本机已安装并登录 Claude Code CLI（终端运行一次 claude /login）。
高级：省 Token（可选，跨议题单独选模型 / 限制单篇文字记录长度）
逐议题小结/发言人标注/演讲稿这些高频调用用上面选的模型；只有"大会总结"这一次调用会用这里填的模型（格式要符合上面选的后端，比如 Anthropic 填 claude-opus-5，OpenRouter 填 anthropic/claude-opus-5）。常见用法：逐议题固定用便宜的模型（比如 haiku），这里单独填个更强的模型做总结——先都用便宜模型跑一遍，觉得总结值得升级，就在这里填更强的模型，勾选相同议题、保持"跳过已经生成过的议题"重新点「开始生成」，已经做完的逐议题小结不会重新调用，只有大会总结会花这次新模型的钱。
超长单集（比如两三个小时的播客）生成小结/演讲稿时只读取前面这么多字符，避免一次调用消耗过多 token；transcripts/ 目录里的原始文字记录始终完整，不受这个上限影响。发生截断时议题列表和日志里都会标出来，不会悄悄发生。

5其它设置与运行

"跳过已生成"具体是什么意思？
同一个输出目录里，之前已经成功生成好的议题不会重新下载字幕或重新调用 LLM；失败的议题不算"已生成"，会重新处理。大批量跑的时候建议保持勾选，中途停止后原样重新点「开始生成」即可从断点续跑。
任务列表（可以在一个任务运行时继续配置/开始下一个，互不影响）
