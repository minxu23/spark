# Summit2MD

给一个 YouTube 峰会播放列表链接（或 Substack 播客链接），自动整理出：

1. 所有议题（演讲/圆桌/工作坊，或播客单集）的链接
2. YouTube 链接：用 `yt-dlp --write-auto-sub` 拉取自动字幕，去重清洗成带时间戳的
   文字记录；Substack 播客链接：直接抓取节目文章正文里自带的官方对话转写
   （已按发言人分段，不是语音识别产物，通常比自动字幕更准确）
3. 每个议题的小结，以及整场大会的总结（大主题、趋势、值得关注的演讲）

带一个本地网页 GUI，不需要命令行操作。

## 运行

Summit2MD 现在是 Spark 的一部分，不再单独启动。在仓库根目录双击
「启动 Spark.command」（或 `python3 spark.py`），浏览器打开落地页后点
**Summit2MD** 卡片，地址是 <http://127.0.0.1:8760/summit/>。

> 启动脚本用 `caffeinate -i` 包住服务进程，处理大批量议题时电脑锁屏/闲置也不会
> 进入休眠导致任务卡住。合上盖子的睡眠不受这个限制，长时间批量处理期间建议保持
> 电脑开盖。

只调试这一个 app 时可以单独跑：`python3 -m apps.summit2md.server`（占用 8765，
前端的相对路径在根路径下同样成立）。

## 使用步骤

1. 粘贴 YouTube 播放列表（或单个视频）链接，或 Substack 播客链接，点「获取议题列表」。
   - Substack 播客站点（包括自定义域名，比如 `dwarkesh.com`）支持三种粘贴方式：
     单集文章页面（`/p/xxx`，只拉这一集）、归档页（`/archive`）或标签页（比如
     `/t/podcast`，拉出该站点全部播客类型的文章，自动跳过普通图文/newsletter）。
     这条路径不走 yt-dlp/语音识别，是直接抓取文章正文里自带的官方转写，速度快、
     没有字幕/语音识别误差；如果某一集页面没有公开转写，那一集会单独报错跳过，
     不影响其它议题。受限于 Substack 自己的存档权限（部分站点只对外公开最近一批
     文章），归档页/标签页有时拉不到全部历史单集，此时可以挨个用单集链接补拉。
   - 输入框下面会显示「最近使用」，记住最近处理过的 10 个链接（存在浏览器本地，
     换个浏览器或清了浏览器数据就不在了），点一下就能重新拉取议题列表，不用再去
     找回原链接。
   - **导入已经生成过的本地目录**（链接输入框下面「高级」里）：适合"之前已经
     生成过，现在想重新生成一遍大会/节目总结"这类场景——直接填已有的输出目录
     路径（比如 `.../output/All-In Podcast`），点「导入目录」，不重新解析播放
     列表/不重新下载，直接把目录里 `.manifest.json` 记录的议题原样带进下面
     「选择议题」，可以照常勾选、只重试失败项、补生成小结/演讲稿，或者单纯
     重新生成总结（保持「跳过已经生成过的议题」勾选，已有内容不会被重新下载）。
     目录里没有 `.manifest.json` 的旧输出也可以导入，会先按老规矩从
     transcripts/speech 目录扫描一遍补出记录。
     - 每次点「获取议题列表」或「导入目录」都会先自动清掉上一个节目残留的议程
       排序、主题总结区域这些设置，不会因为切换到另一个节目而把上一个节目的
       设置带过来；如果想手动清空整个面板（链接、导入路径、名称、内容类型等）
       重新开始，点旁边的「重置」按钮。
     - 如果这个目录之前已经生成过大会/节目总结、且总结里有「主题索引」小节，
       导入之后「选择议题」上方会立刻出现该目录已有的主题勾选列表，可以直接
       勾几个主题点「生成主题总结」，不需要先重新跑一遍任务。主题信息优先读
       `.manifest.json` 里存过的记录，没存过（比如导入了这个功能上线之前生成
       的旧目录）就现读目录里的 `README.md` 解析一遍并回填进 manifest，下次
       就不用重新解析。
   - 工具会自动识别出时长异常长（>3小时）或标题形如
     `... Stage - ... Session` 的条目，标记为「完整场次录像」并默认不勾选
     （这类通常是某个分会场一上午/一下午的连续直播录像，和已经剪好的单个议题
     视频内容重复）。
   - 「内容类型」会自动猜测，依次试三个信号，命中一个就不看后面的：① 播放列表/
     频道标题里的关键词（标题带"Podcast" "Interview" "访谈" "播客"识别成「播客 /
     视频栏目」，带"Summit" "Conference" "峰会" "大会"识别成「会议 / 峰会」）；
     ② 频道的「视频」等标签页链接（如 `youtube.com/@某频道/videos`）默认识别成
     「播客 / 视频栏目」；③ 都判断不出来时，抽样看列表首尾两个视频的发布时间
     跨度，跨度很大（分散在几个月甚至几年）判成「播客 / 视频栏目」，跨度很小
     （集中在一两天）判成「会议 / 峰会」，都拿不到就默认「会议 / 峰会」。这只
     影响生成的总结怎么写、以及产物文件名是编号还是播出日期前缀——峰会总结会
     分析议程结构、策展思路，栏目总结只按内容本身归纳话题，不会把节目往某个
     机构的"内容矩阵"上生拉硬套。猜错了可以在获取议题列表后手动改。
2. 勾选要处理的议题（可以全选、只选独立议题，或用「仅选前N个」先小规模测试）。
   - 表格里还有一列「小结」，配合表格正上方工具栏里的「小结生成范围」选成"仅下表勾选
     的议题"时才生效——可以只给挑出来的几个重点议题生成小结，其余勾选处理的议题仍会
     正常生成文字记录/演讲稿，只是不生成小结（也不会占用摘要调用的时间和花费）。
   - 默认按 YouTube 播放列表原始顺序排列，通常和会议实际议程顺序不一致。可以在
     「会议官网议程页面链接」里填入会议官网的议程/日程页面，点「按议程重新排序」——
     工具会尝试从议程页面里找到每个议题对应的 YouTube 视频链接，按"天 → 时间 →
     分会场"重新排列，议题的文件名编号也会跟着改用议程顺序；页面里没找到对应视频的
     议题保留原顺序排在最后。这是通用解析，不保证适配所有会议官网的页面结构，解析
     不到任何视频链接时会报错，此时保留原始播放列表顺序即可。
   - 重新排序会覆盖浏览器里看到的**全部**议题，不只是当前勾选的这些：点「开始生成」
     时，之前已经在这个输出目录里成功生成过的议题也会先按新顺序重新编号、改名
     （transcripts 和 speech 两边的文件、以及它们之间彼此的链接都会同步更新），
     然后才会去处理这次新勾选、还没生成过的议题——不会因为改了排序规则就把已经
     生成好的内容重新下载一遍。
3. 设置输出目录、字幕语言、是否生成摘要、是否整理演讲稿、摘要后端：
   - **导入的目录已经有大会/节目总结时，默认不会重新生成**：「为每个议题生成小结，
     并生成大会总结」下面会出现一个「沿用已有的总结 / 重新生成一遍」的选择，默认
     "沿用"——这次运行不会再为大会/节目总结额外调用一次模型（省 token），只是照常
     用已有的总结重新拼一遍 README（如果这次有新处理的议题、或者用「按议程重新
     排序」调整过顺序，议题列表和链接会更新，只是总结正文本身不变）。确实想让总结
     反映新处理的内容，手动选"重新生成一遍"。这个选择只影响大会/节目总结这一次
     综合调用，不影响逐议题小结——新处理的议题仍会正常生成小结。没有旧总结可沿用
     时（比如全新的播放列表，或者上一次生成失败——失败占位文本不算"有总结"，不会
     被误当成可以沿用的内容）不会出现这个选择，照常直接生成。
   - **议题小结篇幅**：简洁（一句话结论 + 2-3 个要点）/ 标准（默认，3-5 个要点）/
     详细（5-8 个要点，每点再展开1-2句话说明），只影响每个议题小结本身的详细程度，
     不影响大会/节目总结的篇幅。
   - **小结生成范围**：在上面议题表格正上方的工具栏里设置。默认给本次选中的全部议题
     生成小结；选"仅下表勾选的议题"后，只有议题表格里「小结」列勾选的那些才会真正
     调用 LLM 生成小结，没勾选的议题仍会正常下载字幕、生成文字记录（以及演讲稿，如果
     也勾了那个选项）。
   - **字幕语言**：获取议题列表后会自动探测第一个议题在 YouTube 上实际可选的
     字幕语言，做成下拉菜单（YouTube 自动翻译字幕通常覆盖上百种语言，因此选项
     可能很多）；同一播放列表内不同议题的可选语言可能略有差异，以实际下载结果
     为准。
   - **演讲稿语言**（勾选「整理成演讲稿」后出现）：中文 / 英文（原文，不翻译）/
     中英文对照，三选一。原字幕本身就是中文时，选中英文对照会自动按中文处理。
   - **Anthropic API Key**：最省心，填一个 `sk-ant-...` 即可，或者提前
     `export ANTHROPIC_API_KEY=...` 后留空。
   - **OpenRouter**：单独一个选项，Base URL 已经固定好，只需要填 API Key 和模型名。
     模型名输入框带下拉建议：OpenAI / Gemini / DeepSeek / Kimi (Moonshot) / GLM
     (Z.ai) 每家各给了 1 个旗舰模型 + 1 个性价比模型。大部分选项用的是 OpenRouter
     的 `~xxx-latest` 别名（比如 `~openai/gpt-astra-latest`）——这类别名会自动
     跟随对应系列在 OpenRouter 上的最新版本，不用跟着 OpenRouter 更新模型而手动改；
     没有对应别名的（目前只有 Kimi 的性价比档）固定了一个具体版本号，过期后手动
     换新的即可。也可以直接手动输入别的 OpenRouter 模型 id（带不带 `~latest` 都行）。
   - **第三方 OpenAI 兼容 API**：填写 API Key、API Base URL 和模型名，适用于
     DeepSeek、硅基流动、Moonshot 等提供 OpenAI Chat Completions 兼容接口的服务
     （OpenRouter 也兼容这个协议，但已经有独立选项，不需要走这里）。模型名同样带
     几个常用下拉建议。
   - **把 Key 存成文件，不用每次都填**：把 key 存到
     `~/.spark/keys/anthropic.key` 或 `~/.spark/keys/openrouter.key`（老位置 `~/.summit2md/keys/` 仍然认）
     （文件内容就是 key 本身，一行纯文本），对应的输入框就可以留空——工具会
     自动读取这个目录（和读 `ANTHROPIC_API_KEY` 环境变量是一个原理），界面上会
     提示"已检测到，可以留空"。这个目录不在项目文件夹里，换电脑/删项目目录都
     不受影响，也不会被浏览器保存或提交到代码仓库。
   - **本机 claude CLI**：如果这台机器已经登录过 Claude Code
     （`claude /login`），可以不用 API Key，直接用本机 CLI 调用。
   - **本地 Ollama**：调用本机（或局域网内）已启动的 Ollama 服务，无需 API
     Key、完全离线。需先 `ollama pull <模型>` 把模型拉到本地；模型名输入框会
     自动列出已拉取的模型供选择，地址默认 `http://localhost:11434`，也可以
     填局域网内其他机器的 Ollama 地址。
   - **省 Token：大会总结用的模型**（AI 后端区域「高级：省 Token」里，默认收起，
     可选）：逐议题小结/
     发言人标注/演讲稿这些调用次数多但活儿简单（照模板抠要点），适合用便宜/快的
     模型；大会总结只调用一次但最吃质量，值得单独换个更强的模型。留空则和上面
     「逐议题」用的模型一致。常见用法：先都用便宜模型（比如 haiku）跑一遍，
     觉得总结值得升级，就把这里换成更强的模型（比如 opus），勾选相同议题、
     保持"跳过已经生成过的议题"重新点「开始生成」——已经做完的逐议题小结不会
     重新调用，只有大会总结会花这次新模型的钱。选择栏上方会实时显示这次大概
     要调用几次模型，方便估算成本。这个字段也带下拉建议（根据当前选的后端换一套
     常用模型名），可以直接选，也能手动输入别的。
   - **省 Token：单篇文字记录读取上限**（AI 后端区域「高级：省 Token」里，默认
     收起，可选）：默认
     120000 字符。超长单集（两三个小时的播客很常见）生成小结/演讲稿时只会读取
     前面这么多字符，避免一次调用消耗过多 token；`transcripts/` 目录里的原始
     文字记录不受这个上限影响，永远完整。截断不会悄悄发生——发生截断的议题在
     议题列表标题前会标 ⚠️，README 开头也会列出具体是哪几篇。填 `0` 表示不限制。
   - **大会/节目总结的最后一节是「主题索引」**：前面「分主题看点」（峰会）/
     「分类看点」（栏目）已经会按内容自动分组分析；「主题索引」把同样的分组
     再列一遍成可点击的链接列表（主题 → 该主题下的议题，直接跳到对应议题的
     演讲稿/文字记录），方便按主题快速跳转，不用在长文里找。
   - **按主题单独生成聚焦总结**：任务跑完之后，结果区域会出现按主题索引解析出的
     勾选列表（比如"AI 安全治理（4 个）"），勾选一个或几个主题、点「生成主题总结」，
     就会把这些主题下的议题单独抽出来，复用它们已有的议题小结再合成聚焦总结，存到
     输出目录下的 `topics/` 里，不重新下载字幕、不重新调用逐议题小结。勾选了不止
     一个主题时，勾选列表下面可以选：**合并成一份综合报告**（默认，一次调用把选中
     的几个主题合成一份，跨主题重复的议题只算一次）或**每个主题分别单独出一份**
     （依次对每个主题单独调一次，各出一份独立的 `topics/<主题名>.md`，互不合并，
     某一个主题生成失败不影响其它几个，不用再一个个勾选、一个个点）。用的模型优先
     取"大会总结用的模型"（省 Token 里那个可选项），没填就用逐议题的模型。这个功能
     依赖大会/节目总结成功解析出「主题索引」；比较旧的、这个功能上线前生成的输出
     目录不会显示这个勾选列表，需要重新生成一次总结（`skip_existing` 保持勾选，
     逐议题小结不会重新调用）。
   - **手选议题生成聚焦总结**：跟上面那条是平行的两条路——上面按模型自动分出的
     主题选，这条直接从全部议题的原始列表里勾几个你自己感兴趣的，不依赖、也不
     需要大会/节目总结解析出「主题索引」（没生成过总结、或者模型这次没按格式
     输出主题索引的目录，一样能用）。任务跑完之后、以及导入已有目录之后都会出现
     「手选议题生成聚焦总结」这个勾选列表，逐个列出这个目录里的全部议题（处理
     失败的会标出来、不能勾）；勾好想要的几个、可以填一个标题（留空就自动叫
     "手选 N 个"），点「生成主题总结」，复用这些议题已有的小结合成一份聚焦总结，
     存到 `topics/` 下，跟按主题选出来的结果放在同一个目录、互不冲突。用的模型
     同样优先取"大会总结用的模型"。
   - **跳过已经生成过的议题**：默认勾选。同一个输出目录里之前已经成功处理过的
     议题不会重新下载字幕、重新调用 LLM；这是"续跑"和"只重试失败项"的基础，大批量
     跑的时候建议保持勾选。
4. 点「开始生成」，实时看进度和日志：
   - 每次点「开始生成」都会在下面「任务列表」里新增一张独立的任务卡片，各自轮询
     进度、互不影响；可以在一个任务还在跑的时候，直接改链接/设置再点一次「开始
     生成」去开始另一个任务，不需要等当前任务跑完，也不需要开多个浏览器标签页。
     同一个输出目录（即同名会议）已有任务在跑时会拒绝重复启动，避免两边同时写
     同一批文件。
   - **刷新浏览器不会丢失任务**：任务实际在服务端后台线程里跑，跟浏览器页面本身
     没关系；刷新页面（或者关掉标签页再重新打开）会自动把服务端还记得的任务
     （运行中 + 最近完成的）重新拉回来接上进度条/日志，暂停/继续/停止/在 Finder
     中打开也照常能用。唯一的限制是"重试失败项"和"生成主题总结"这两个按钮——
     刷新之后原来填的 API Key/模型/自定义输出目录这些信息就丢了，卡片上会有
     一行提示：这两个按钮会改用默认后端（Anthropic API Key 文件 + 默认模型）
     执行，如果当时用的是其它后端或者自定义了输出目录，就不要点这两个按钮，
     回到上面重新配置手动处理。真正重启服务（`python3 spark.py`，而不只是刷新页面）
     会清空这份内存记录，跑到一半的任务就彻底看不到了，但已经写盘的文件不受
     影响，重新打开页面照原设置点「开始生成」、保持"跳过已经生成过的议题"，
     就能从断点接着跑。
   - 进度条旁边会显示「预计剩余」时间，根据最近几个议题的实际处理速度估算，
     只是粗略参考——跳过已生成的议题几乎不耗时，会让估算一开始偏乐观，实际
     开始下载字幕/调用 LLM 后会自动修正。暂停期间不计入估算。
   - 开始处理前，日志会先给一句概览，比如"本次共选中 175 个议题：140 个跳过
     （已生成过），2 个只补缺失部分（小结/演讲稿），1 个重试此前失败的议题，
     32 个全新处理"——一眼看出这次运行实际要做什么，避免把"重试之前失败过的
     议题"误看成"已完成的内容又被重新处理了一遍"。处理到某个此前失败过的议题
     时，日志也会附带原因，例如"下载字幕：xxx（此前失败过：未找到可用的自动
     字幕，现在重试）"。
   - **暂停 / 继续**：暂停会在处理完当前这一条之后停下来等待，不会中断正在下载/
     调用 LLM 的那一条；点继续会从下一条接着跑，不需要重新开始。
   - **停止**：和暂停类似，但会在处理完当前议题后结束这次运行，并根据当前已有产物
     生成 README；停止后不会再发起耗时的大会总结调用（已有大会总结会保留）。因为有
     "跳过已经生成过的议题"这个机制，停止之后原样重新点「开始生成」就是续跑，不需要
     专门的"恢复"操作。
   - 完成后如果有失败的议题，会出现「重试失败项」按钮，一键只重新处理失败的那些
     （沿用这次跑的配置），不用手动去表格里重新勾选。
   - 完成后可以直接在 Finder 里打开输出目录。
   - 任务卡片标题旁边有个「关闭」按钮（任务完成/失败后才会出现），点一下把这张卡片
     从任务列表里移除，不影响已经生成的文件；服务端那份记录也会一起清掉，不会因为
     刷新页面又被重新捞回来。

## Podcast 跟进的订阅

「Podcast 跟进」入口跟「信息跟进」一样有三个标签页：

- **订阅管理**：添加想长期跟的节目（Substack、播客 RSS、Apple Podcast、YouTube
  节目频道/播放列表），按类别分组；每个节目可以单独勾「自动检查」，整个类别也能
  一起勾。批量导入里的「填入以前处理过的节目」会在输出目录里找用「临时链接」处理
  过、还没订阅的节目，按原来的文件夹名订阅——订阅后沿用那个文件夹，已经处理过的
  单集算已处理。
- **新单集**：打开页面时只检查勾了「自动检查」的节目（只列标题，不调模型），列出
  比已处理的最新一期还新的单集——以前处理过一部分的节目，更早那些从没处理过的
  往期不算新单集（订阅详情里会说有多少期；要补就在「临时链接」里勾选处理），处理
  失败过的照样列出来可以重试。一期都没成功处理过的节目列出全部。源里没有播出日期
  时（YouTube 播放列表/频道），按处理过的几期（文件名带日期）推断列表是新在前还是
  旧在前；老版本按编号命名、推断不了的，YouTube 频道页按"新在前"处理（播放列表
  不做这个假设，列出全部）。勾选后点「更新选中的单集」，每个节目启动一个跟「临时链接」
  同一套的处理任务：逐期小结和文字记录写进节目文件夹（`输出目录/节目名/`），再
  刷新节目总结；进度在页面下方的任务列表里，跑完会自动重新检查这个节目。不会
  在没点的时候自动调模型。
- **临时链接**：原来的「粘贴链接 → 选择单集 → 开始生成」流程，不变。

订阅管理顶部的 **筛选更新**：按时间范围（最近 3 天 / 一周 / 一个月 / 全部）+ 话题找
单集。处理过的单集带小结，话题默认交给模型按意思匹配（搜"RSI"也能找到讲递归自我改进
的），不勾就按关键词找；还没处理的只包括这一页检查过的订阅，只有标题，勾上可以直接更新。

每期的输出：节目文件夹根目录下一篇 `2026-09-12 标题.md` 单集笔记（frontmatter 带
节目/播出/时长/嘉宾/话题/链接；一句话结论、本期要点、带时间戳的分段、观点与分歧、
值得记下的话、预测与判断），要点多少跟时长走——半小时以内 3-5 条，一个半小时的 10-15
条且每条展开。`speech/` 里的双语整理稿和 `transcripts/` 里的完整文字记录不变。节目
主页（`节目名.md`）是「节目总结（内容总结 + 长期主线）+ 按月份倒序的全部单集」，
节目总结每次只把新处理的单集并进去。

订阅跟信息跟进的存在同一个 `subscriptions.json` 里，用 `kind` 区分（老订阅没有
这个字段，算信息跟进），两个页面各看各的，类别也各管各的。

## 输出结构

```
<输出目录>/<会议名称>/
  README.md              # 大会总结（篇幅较长，含分析与举例）+ 全部议题一览表
  speech/                 # 主目录：勾选「整理成演讲稿」后，每个议题一篇文档
    001_xxx.md            #   含：链接、时长、议题小结、原文/中文对照的演讲稿正文
    002_xxx.md            #   大会类（summit）用处理顺序编号；播客/访谈类（series，
    20260911_xxx.md       #   YouTube 播客频道或 Substack 播客）用播出/发布日期
    ...                   #   （YYYYMMDD）做前缀，方便直接从文件名看出期数时间
  transcripts/            # 原始文字记录：带时间戳，供核对/排查用
    001_xxx.md            #   未勾选「整理成演讲稿」时，议题小结留在这里
    20260911_xxx.md
    ...
  .cache/subtitles/       # 原始字幕缓存（YouTube 来源为 vtt，Substack 来源为 json），供排查问题用
  logs/                   # 每次点击“开始生成”都会新增一份带时间戳的持久化任务日志
    task_YYYYMMDD-HHMMSS_<任务ID>.log
  .manifest.json          # 处理进度清单，续跑/跳过已完成/重试失败项都靠它，不用手动管
```

演讲稿正文的语言由界面上的「演讲稿语言」选项决定（中文 / 原文 / 中英文对照），
默认中英文对照时按「一段原文 + 一段中文翻译（引用块）」交替排列。议题小结只会
出现在一个地方——生成了演讲稿就放在 speech 目录对应文档里，没生成（未勾选该
选项，或该议题整理失败）则留在 transcripts 目录对应文档里，不会重复也不会丢失。

只要能拿到某个议题的播出/发布时间，文档正文里「时长」那一行下面就会多一行
「播出时间：2026-09-15」——不管是大会类还是播客/访谈类都会记录，不止是播客/
访谈类才有，方便查一场演讲/一期节目具体是什么时候播出的，不用跳回 YouTube 查。

文件名前面的编号（如 `005_xxx.md`）反映的是当前已知的最新顺序：做过「按议程重新
排序」用的是议程里的真实顺序，没做过就是播放列表原始顺序；每次重新排序，已经
生成好的文件也会跟着改名同步，不会停留在旧编号。这套编号只用于大会类（summit）
内容——播客/访谈类（series，「选择议题」页面显示「所属节目」而不是「所属会议」
的那种）节目不用编号，而是直接用节目播出/发布日期（`YYYYMMDD`）做前缀：Substack
播客用文章发布日期；YouTube 播客/访谈频道用视频上传日期（下载字幕时顺带取回，
不用额外请求），同一天发布多期时后面会加 `_2`、`_3` 区分；已经生成过的文件不会
因为后续重新处理而改名。少数情况下视频上传日期拿不到（比如该视频的字幕文件之前
已经缓存过，这次没有重新请求 YouTube），就还是退回用处理顺序编号。README.md 里
的表格汇总的是这个输出目录里**累计处理过的全部议题**，不只是最近一次运行选中的那些——分好
几批跑、或者只重试失败项，最后的 README 仍然是一份完整索引。

**这个功能上线之前生成的播客/访谈类旧内容**（文件名还是 `001_xxx.md` 这种编号）：
处理完成后，任务卡片的结果区域会出现「按播出日期重命名文件」按钮（只在播客/
访谈类节目才会出现）。点一下会：给 manifest 里还没记录播出日期的 YouTube 议题
补一次轻量元信息请求（不重新下载字幕/正文，比正常处理快很多；Substack 议题
一般发现阶段就带了日期，不用补）；把文件从编号命名改成日期前缀命名；同步修正
manifest、transcripts/speech 两边互相的链接、以及 README；顺便把「播出时间」
那一行也补进旧文档正文。整个过程不需要 API Key，纯本地改名 + 少量元信息请求，
可以放心重复点（已经是日期前缀的文件会跳过，不会重复改）。

`.manifest.json` 不存在或者是在这个功能上线之前生成的旧输出目录，工具会在第一次
运行时自动扫描 transcripts/speech 目录下已有的文件、把它们补登记进清单（日志里会
提示"已将输出目录里 N 个已存在的旧产物纳入续跑记录"），不需要手动处理，旧文件也
不会被当成没处理过而重新生成。

同一视频重新生成时会按视频 ID 复用 manifest 中已有的 `transcripts/` 与 `speech/`
文件路径，并直接原位覆写；不会因为原文件名已存在而创建 `_2.md`、`_3.md`。旧版本
已经产生的这些副本不会被自动删除（避免误删手工修改内容），但 manifest 会优先恢复
指向不带 `_2` 后缀的原始文件。

## 说明 / 已知限制

- YouTube 来源：字幕是 YouTube 自动生成的，可能有识别错误（人名、专业术语尤其
  容易错），请以视频原声为准；自动字幕没有说话人分离信息，`speaker_change`
  依赖字幕自带的 `>>` 标记 / 标题解析 / LLM 上下文推测，不是精确的说话人识别。
- Substack 来源：优先抓取文章正文里带时间戳、按发言人分段的官方「Transcript」
  小节，比 YouTube 自动字幕更准确。有些单集页面没有这种结构化转写，这时会
  按下面两种情况自动兜底：(1) 正文很短、只有一句"这是我上周那篇文章的语音
  朗读版，完整原文在这里"之类的话附带链接——自动跟着链接抓取原文章的正文；
  (2) 正文本身就是完整的图文/清单型文章（发布在播客分类下，但没有对话转写
  这种结构）——直接把正文按段落抠出来用。这两种兜底情况下都没有真实发言人
  分段（整篇当独白处理），也没有真实的分段时间戳（时间戳统一显示为视频/文章
  开头）。只有当正文完全没有可用内容（比如整页只有一句付费墙提示）时才会
  单独报错跳过。归档页/标签页发现到的单集数量取决于 Substack 对外公开的
  存档范围，不代表该节目的全部历史单集。
- 演讲稿（speech 目录）由 LLM 改写、翻译生成，力求保留原意、不做总结；中英
  对照模式先整理出原文版本、再单独逐段翻译成中文（拆成两步是为了不让模型在
  "保持原文"和"翻译成中文"之间顾此失彼），如果翻译这一步失败会自动降级为
  只保留原文。无论哪种模式都可能存在改写/翻译误差，或（对超长内容）截断，
  请以 transcripts 目录下的原始文字记录和视频原声为准。
- 大会总结（README.md）要求 LLM 输出较长篇幅（3000 字以上），实际长度取决于
  模型发挥，个别情况下可能达不到目标篇幅。议题特别多的大会（比如上百个）因为
  "分主题看点"和"主题索引"两节要把每个议题标题至少列两遍，所需篇幅会明显更长；
  单次调用有输出长度上限，议题数量极多时仍有可能被截断（Anthropic API 后端
  已经关闭了这类改写/归纳任务不需要的思考过程、并调高了输出上限，缓解了这个
  问题，但没有绝对上限保证）。
- 处理大量议题（比如上百个）会比较慢，且如果开启摘要 / 发言人标注 / 演讲稿
  整理，会产生相应数量的 LLM 调用（有实际花费/用量；演讲稿要改写并翻译全文，
  单次调用的 token 消耗明显高于小结），建议先用「仅选前N个」小规模测试。
- 「按议程重新排序」是针对"标签页/时间线卡片 + 每场附 YouTube 链接"这类常见议程
  页面结构写的通用解析，不同会议官网的页面结构差异很大，不保证每个会议官网都能
  解析成功；解析不到就保留原始播放列表顺序，不影响正常处理。
- 「跳过已经生成过的议题」是按整篇议题跳过的：如果之前跑的时候没开「整理成演讲稿」，
  后来想给已经处理过的议题补生成演讲稿，会连字幕下载、小结一起重新做一遍（不是只
  补生成缺的那部分），这种场景下会有一些重复的 LLM 调用，属于已知取舍，不算 bug。
