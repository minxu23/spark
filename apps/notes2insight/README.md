# Notes2Insight

从 Obsidian 笔记库里**勾选若干篇笔记**，或直接**拖入文件**，生成一份带证据编号、
分歧梳理与展望的**技术洞察报告**。

浏览器里点选，本地跑，报告直接落回笔记库的 `output/` 目录，可以在 Obsidian 里当普通笔记打开。

三种用法：

```
主题模式：输入主题 → 自动检索相关笔记 → 判定相关度 → 自动勾选 → 生成专题报告
手动模式：自己从笔记树里勾选 → 生成技术洞察报告
拖入文件：材料还没整理进笔记库也没关系 → 拖 .md/.txt/.pdf/.docx 进来 → 生成技术洞察报告
```

共同的后半程：

```
选中的笔记  →  每篇压成技术摘要卡  →  跨卡归纳主题骨架  →  分章成文  →  Markdown 报告
```

---

## 快速开始

Notes2Insight 现在是 Spark 的一部分，不再单独启动。在仓库根目录双击
「启动 Spark.command」（或 `python3 spark.py`），浏览器打开落地页后点
**Notes2Insight** 卡片，地址是 <http://127.0.0.1:8760/notes/>。

首次运行会自动装依赖（flask、anthropic、python-pptx）。默认读取
`~/Documents/Obsidian/minxu`，可在界面上改，也可以用 `SPARK_VAULT` 环境变量覆盖。

想换端口：`SPARK_PORT=9000 python3 spark.py`。要停掉服务，在启动器那个终端窗口
按 Ctrl+C。

只调试这一个 app 时可以单独跑：`python3 -m apps.notes2insight.server`。

## 用法

### 主题模式（默认）

输入一句话主题，例如「AI 推理成本与 Token 经济学」，点「检索相关笔记」。三步自动完成：

1. **扩词**：模型把主题扩成 15-28 个中英文检索词（笔记库是中英混排的，只用中文会漏一半）。
2. **本地全文检索**：BM25 变体扫全库，中文子串计数、英文带词边界，4600 篇 / 82MB 约 3 秒，不花模型调用。
   同一期内容在库里存两份（整理稿 + 逐字稿）会按标题+日期去重。
3. **相关度判定**：只把打分最高的候选（默认 40 篇）送给模型，按标题+命中片段打 0-5 分并给一句理由。

结果列表按相关度排序，**相关度 ≥3 的自动勾选**（不超过「入选上限」）。可以自己增减，再点生成。
想一步到位就先点亮「检索完直接生成」，检索结束会自动开跑。

实测：主题「AI 推理成本与 Token 经济学」、最近 90 天 → 扫描 604 篇，命中 220 篇，去重 97 篇，
判定 40 篇，自动选中 15 篇，全程约 2 分钟。

报告的「方法」一节会写清这批笔记是怎么选出来的，附录里列出实际用的检索词，以及**打分靠前但被判为不相关而未纳入**的笔记——
这样你能判断召回够不够全，而不是只能相信结果。

生成的报告默认不会再被检索到（「排除输出目录」默认勾选），免得报告越滚越自我引用。

### 手动模式


- 按文件夹折叠浏览，点文件夹行展开；勾选文件夹复选框＝全选该文件夹。
- 搜索框支持多关键词（空格分隔，标题与路径都匹配），配合「最近 N 天」「按日期/篇幅排序」缩小范围。
- 「全选当前结果」会选中**全部**筛选结果（不止屏幕上显示的那 400 行）。
- 文件夹复选框只管**该层**的笔记，子文件夹是独立的一行，需要单独勾。
- 勾选 20 篇以上时，点「生成」会先弹一次确认，把篇数、档位和预估耗时摆出来。
- 点笔记标题可预览正文前 3000 字，确认是不是想要的那篇。
- 选择栏实时显示：已选篇数、总字数、预计耗时。

### 拖入文件模式

不需要先把材料整理进笔记库——把 `.md` `.txt` `.pdf` `.docx` 拖进这个 tab，或点击
选择，就能直接生成报告。

- 文件落在一个临时目录里，只用于这一次生成，不会被当成笔记库的一部分保存下来；
  关掉页面/重启服务之后（默认 7 天）会被自动清理。
- 支持在同一个页面会话里分几次拖拽——后面拖进来的文件累积在同一批，不会覆盖之前的。
- 单个文件不超过 30MB；PDF 走 `pypdf` 抽取文字，抽不出内容（多数是扫描件/图片版，
  没有文字层）会明确报错，不会悄悄生成一篇空笔记；docx 走 `python-docx` 抽取段落。
- 不支持的格式、超限文件单独报错，不影响同批里其它文件正常处理。
- 上传成功的文件默认全部勾选，取消勾选可以把某一篇排除在报告之外。
- 来源索引里这些笔记只有 `[[双链]]`，点不开——它们本来就不在笔记库里，这是预期
  行为，不是链接坏了。真想回溯原文，请看报告「方法」一节里写的原始文件名。

### 报告设置

- **关注点**：可留空。写清楚想看什么，报告会围绕它组织。
  例如「这批材料里关于推理成本与自研 ASIC 的路线分歧」。

  可以在这里写一整段报告规格（要哪些章节、结论口径、要不要行动建议），但要知道它分两处生效：

  | | 摘取阶段（每篇笔记一次） | 归纳与成文阶段 |
  |---|---|---|
  | 收到什么 | 主题模式用**主题**；否则用关注点的**第一句** | **完整关注点** |
  | 为什么 | 一整段报告要求重复几十遍既费 token，也会把摘要卡措辞带偏向"报告结构" | 这里才真正决定报告长什么样 |

  报告的「方法」一节会写明摘取阶段实际按什么定向。
  另一个好处：**只改后半段规格不会让摘要卡作废**（缓存键跟的是摘取阶段那句），改完重跑只花成文的钱。
- **深度**：

  | 档位 | 章数 | 实测篇幅 | 适合 |
  |---|---|---|---|
  | 简报 | 3 | 约 5000-8000 字 | 3-8 篇笔记，快速摸清共同主线 |
  | 标准 | 6 | 约 1.2-1.8 万字 | 10-40 篇，一个议题的完整梳理 |
  | 深度 | 9 | 约 3 万字以上 | 40 篇以上，季度级综述 |

- **输出目录**：默认 `笔记库/output`，生成后立刻能在 Obsidian 里看到。

### 模型后端

先选后端，模型下拉会跟着换成该后端可用的选项：

| 后端 | 模型下拉里有什么 | 说明 |
|---|---|---|
| 本地 claude CLI（默认） | 默认（跟随 CLI 当前设置）、sonnet、opus、haiku | 走本机已登录的 Claude Code CLI，不另外计费到 API Key |
| Anthropic API | claude-sonnet-5、claude-opus-5、claude-haiku-4-5-20251001 | 按 token 计费；一份报告要几十次调用，先小样本试跑 |
| OpenRouter | anthropic/claude-sonnet-5、opus-5、haiku-4.5、deepseek/deepseek-chat-v3.1、google/gemini-2.5-flash、moonshotai/kimi-k3、kimi-k2.5、z-ai/glm-5.3、glm-5.3-flash | 一个 Key 用所有厂商的模型；模型 id 见 openrouter.ai/models，没列的选「自定义」手填 |
| OpenAI 兼容第三方 | 自定义（手填模型名） | 例如 deepseek-chat，另需填 API Base URL |
| 本地 Ollama | 已 `ollama pull` 到本地的模型 | 检测不到就选「自定义」手填，工具会直接调 |

每个下拉最后都有「自定义…」，选中后出现输入框，可以填任何该后端认识的模型名。

**API Key 可以不用每次填**：Key 输入框留空时，服务端按下面的顺序找，和 summit2md 共用同一个目录，配一次两个工具都能用：

| 后端 | 查找顺序 |
|---|---|
| Anthropic API | 请求里填的 Key → 环境变量 `ANTHROPIC_API_KEY` → `~/.spark/keys/anthropic.key`（老位置 `~/.summit2md/keys/` 仍然认） |
| OpenRouter | 请求里填的 Key → 环境变量 `OPENROUTER_API_KEY` → `~/.spark/keys/openrouter.key`（老位置 `~/.summit2md/keys/` 仍然认） |

key 文件的内容就是 key 本身（前后空白会去掉）。检测到文件时界面会直接提示「已检测到 …，可以留空」，环境提示条里也会列出来。Key 不写进浏览器本地存储，也不写进报告。三方后端（OpenAI 兼容）的 Key 仍需每次填，只随本次请求发给本机服务端。

**模型选择按后端分别记住**：CLI 下选了 opus、API 下选了 haiku，来回切换各自保持不变，下次打开也还在（存在浏览器本地）。

### 省钱：分阶段用不同模型

勾上「分阶段用不同模型」，摘取和成文可以各选各的：

| 阶段 | 调用次数 | 活儿的性质 | 建议 |
|---|---|---|---|
| 摘取（含长笔记分块、批次预归并） | 每篇至少 1 次，长笔记每 2.8 万字多 1 次 | 结构化抽取，照着模板填 | **小模型**（haiku） |
| 归纳骨架 + 成文 | 章数 + 3 次 | 跨材料推理与写作，最吃质量 | **大模型**（sonnet / opus） |

15 篇笔记的标准档大约是「25 次摘取 + 9 次成文」——把那 25 次换成 haiku，省的是大头。
选择栏会实时显示 `N 次摘取 + M 次成文`，改任何设置都能立刻看到影响。

**摘要卡缓存只跟摘取模型绑定**：换成文模型重跑不会重新摘取，只有换摘取模型才会。
所以推荐的流程是——摘取固定用 haiku，成文先 sonnet 跑一版，觉得值得再用 opus 重跑一次，第二次只花成文的钱。

### 省钱：单篇长度上限

默认「10 万字」。知识库里绝大多数笔记远小于这个数，只有超长逐字稿和论文会被截断。
这一项省的是分块调用：一篇 37 万字的论文，不限制要 15 次摘取调用，限到 5 万字只要 3 次。

截断不会悄悄发生——**只要有笔记被截断，报告的「局限」一节会列出是哪几篇、只读了多少**。
要完整性优先就选「不限制」。

检索阶段的相关度判定也跟着摘取模型走（同样是量大活简单）。

### 生成

进度分三段：摘取 → 归纳骨架 → 撰写正文。日志实时滚动。生成完可以预览全文、复制、下载 `.md`，文件同时已写入输出目录。

**刷新页面不会丢现场。** 任务跑在服务端，页面只是个看板：

| 刷新时的状态 | 重新打开后 |
|---|---|
| 任务正在跑 | 自动接上，进度条、完整日志、禁用的按钮都回来，顶部提示「已接上正在运行的任务」 |
| 任务已完成 | 直接显示上一份报告的结果与预览 |
| 任务失败了 | 显示当时的错误与日志 |
| 本地存储被清掉 / 换了浏览器 | 向服务端要最近的任务列表，仍能认回正在跑或刚跑完的那个 |

勾选的笔记、展开的文件夹、检索出来的候选列表也一并恢复，**恢复时不会重新自动勾选**，保留你刷新前调整过的选择。

两种情况确实恢复不了：服务重启过（任务状态在内存里），以及任务超过 24 小时。
但报告文件早就落盘了，去输出目录找即可。

### 演示：交互 HTML / PPTX / PDF

报告是几万字的长文，隔几周回头看没人愿意从头读一遍。界面第 6 块「交互演示」把任意一份报告压成
**一个自包含的 HTML 文件**，存在报告旁边（`xxx.deck.html`）。

- **结论在页标题上**：每页标题写的是判断（「推理单价两年掉两个数量级」），不是话题。
- **`[N]` 角标可以点**：点开右侧抽屉，显示这条依据来自哪篇笔记，一键 `obsidian://` 跳回原文。这是自己回顾时最值钱的部分。
- **键盘操作**：`←` `→` / 空格翻页，`Esc` 缩略图总览，`S` 看备注（"当时为什么这么判断"），`F` 全屏。
- **导出 PDF**：在演示里按 `P`（或 `Cmd`+`P`），一页一张横版 PDF，备注自动展开。
- **零依赖**：没有外链、没有构建步骤，拷到任何地方双击就能开，离线可用。

做法是先**确定性地**从 Markdown 里抽骨架——摘要 / 判断 / 分歧 / 展望 / 启示整节保留，每章只留小标题和首段，
一份 4 万字的报告压到 1.8 万字——再用**一次**模型调用排成幻灯片脚本，最后纯 Python 渲染。
所以它只花一次便宜调用，跟报告本身的成本比可以忽略。实测：2 万字报告约 1.5 分钟，4 万字 / 21 篇来源的报告约 3.5 分钟，费用都在一分钱上下。

> ⚠️ 这一步默认跟着**摘取模型**走。别用思考型模型（`kimi-k3`、`glm-5.3` 系列）：
> 它们的思考过程也计入 `max_tokens`，容易把预算烧光、返回空内容。`claude-haiku-4.5`、
> `deepseek-chat-v3.1`、`gemini-2.5-flash` 这类非思考型模型合适。

勾上「同时生成 .pptx」会用**同一份幻灯片脚本**再渲染一个 PowerPoint，存成 `xxx.pptx`：

- 16:9。字体不钉在正文上，而是改**主题**的脚本映射：默认主题把简体中文映射到宋体（衬线），
  这里换成黑体（`微软雅黑`——Windows 自带，macOS 上没有会落到系统默认的 PingFang，两边都是无衬线）。
  想换字体在 PowerPoint 的「主题字体」里改一次就能换全篇。
- PPTX 里点不开角标，所以来源走两条路：正文后面留 `[N]`，**备注页**写清楚每个 `[N]` 是哪篇笔记、在库里什么位置；来源索引页的笔记名带 `obsidian://` 超链接。
- 来源超过 14 条会自动分页，不会让表格掉出版心。

**已经生成过演示的报告（下拉里标 `◆`）会多出一个「补出 .pptx」按钮**：直接从 `.deck.html` 里读回内嵌的幻灯片脚本重新渲染，**不再调用模型**，一秒出结果。想换格式、或者改完渲染器想重出一遍，都走这条路。

下拉里列的是输出目录下所有 `.md`：`◆` = 有 HTML 演示，`▣` = 有 PPTX。

| 格式 | 适合 | 来源可追溯性 |
|---|---|---|
| `.deck.html` | 自己回顾 | 最好——点角标开抽屉，一键跳回 Obsidian |
| `.pptx` | 给别人看/改 | 备注页写清来源，索引页带超链接 |
| PDF | 存档、打印 | 在 HTML 里按 `P` 导出，备注自动展开 |

## 报告长什么样

```
frontmatter（标题 / 日期 / 覆盖时间范围 / 来源篇数 / 关注点 / 深度）
标题 + 副标题 + 一句话生成说明
阅读地图（各章主题与核心张力的表格）
执行摘要
关键判断        6-10 条，每条「结论 + 机制 + 证据 + 何时失效」
第 1..N 章      每章：事实状态 → 技术机制 → 材料间印证与冲突 → 核心张力
分歧与开放问题   每组列出双方主张、各自依据、目前无法判定的原因
信号与展望      三种情景（基线/加速/受阻）+ 8-12 个可观测信号
启示            5-8 条可执行结论
方法、来源与局限 + 来源索引表（Obsidian 双链回原笔记）
附：报告骨架（折叠，供核对模型的中间归纳结果）
```

正文里的 `[3]` 这类编号对应文末来源索引表，可以直接回溯到是哪篇笔记支撑了这个说法。

## 工作原理

**阶段一 · 摘取（并发）**
每篇笔记生成一张结构化摘要卡：一句话主旨 / 核心技术论点 / 关键事实与数据 / 时间锚点 / 涉及主体 / 判断与预测 / 分歧与不确定 / 可引用原话。
超过 28000 字的长笔记先按段落边界切块，逐块出卡后再合并成一张。单篇失败不会中断任务，会在来源索引里标注 ⚠️。

**阶段二 · 归纳**
所有摘要卡合起来产出报告骨架：主题簇（含相关笔记编号）、全局判断、主要分歧、时间线。
卡片总量超过 9 万字时，先分批压成「批次要点」再统一归纳，保证不超上下文。

**阶段三 · 成文**
按骨架逐章生成，每章只带**属于该主题簇的摘要卡**，所以章节数越多、材料越聚焦，细节密度越高。最后拼上 frontmatter、阅读地图、来源索引。

**阶段四 · 演示（可选，单独触发）**
报告 Markdown → 确定性抽骨架 → 一次模型调用产出结构化幻灯片脚本（页面类型 / 要点 / 来源编号）→ Python 渲染成单文件 HTML 和 / 或 PPTX。
来源编号会跟报告的「来源索引」表核对，模型编造的编号直接丢掉，点不开的角标不会出现。
幻灯片脚本内嵌在 `.deck.html` 里，所以补渲染另一种格式不需要再花一次模型调用。

**缓存**
摘要卡按「笔记路径 + 修改时间 + 关注点 + 后端 + 模型」哈希缓存在 `.cache/digests/`。
换个关注点重跑会重新摘取；只是调深度或补几篇笔记，已摘过的部分直接复用，第二次生成快很多。缓存可在界面上关掉。

## 耗时参考

实测（本地 `claude` CLI，并发 3）：**3 篇笔记（合计约 4 万字）+ 简报档 ≈ 9 分钟**。

粗略估算：`摘取耗时 ≈ 篇数 ÷ 并发数 × 50 秒`，`成文耗时 ≈ (章数 + 2) × 80 秒`。
界面上的「预计耗时」就是按这个公式算的。笔记很多时建议先用简报档跑一遍看骨架对不对，再上标准/深度档。

## 已知限制

- 单次最多 400 篇笔记（`pipeline.MAX_NOTES`）。
- 结论只覆盖所勾选的笔记，不代表领域全貌；报告末尾会自己声明这一点。
- 播客类笔记本身是语音转写 + AI 整理的产物，数字和人名可能有误，引用前请按来源索引回溯原文。
- 摘要卡是有损压缩：需要逐句精读的材料，不要指望报告替代原文。

## 排错

| 现象 | 处理 |
|---|---|
| 「未检测到 claude CLI」 | 装 Claude Code CLI，或在界面切到 Anthropic API 并填 Key |
| 「claude CLI 未登录」 | 终端执行 `claude /login` |
| 调用超时 | 高级设置里把单次调用超时调大（默认 900 秒），或把并发降到 1-2 |
| 扫不到新笔记 | 点「重新扫描」（会跳过缓存重新解析文件头） |
| 报告章节太笼统 | 选中的笔记主题跨度太大，拆成几份分别生成；或把关注点写得更具体 |
| 主题检索没找到该找的笔记 | 看报告附录里的检索词够不够具体，把主题写得更像「领域词 + 具体问题」；或放宽时间范围、调大候选篇数 |
| 候选里出现同一期的两份 | 逐字稿与整理稿标题不完全一致时去重会漏，手动取消勾选即可 |
| 提示「已经在运行」 | 说明另一个窗口里还开着服务，直接用它；要重启就先去那个窗口 Ctrl+C |
| 想换端口 | `SPARK_PORT=9000 python3 spark.py`（单独调试时 `NOTES2INSIGHT_PORT=9000 python3 -m apps.notes2insight.server`） |
| 改了代码但界面行为没变 | 前端改动刷新页面即生效，**Python 侧改动必须重启服务**（Ctrl+C 后重新双击启动器） |

## 文件说明

| 文件 | 作用 |
|---|---|
| `server.py` | Flask 本地服务，任务队列与进度查询，只监听 127.0.0.1 |
| `search.py` | 主题检索：关键词扩展、BM25 本地打分、相关度判定 |
| `pipeline.py` | 三阶段流水线、提示词、报告组装 |
| `deck.py` | 报告 → 演示：抽骨架、排幻灯片、渲染 HTML 与 PPTX |
| `vault.py` | 笔记库扫描与元数据缓存（4600 篇冷扫描 0.7 秒，缓存后瞬时） |
| `llm.py` | 转发到 `core/llm.py`：五种模型后端；key 文件读取见 `core/keys.py`（`~/.spark/keys`） |
| `uploads.py` | 「拖入文件」的文字抽取（.md/.txt/.pdf/.docx）与临时目录管理 |
| `static/` | 前端界面 |
| `.cache/` | 笔记索引与摘要卡缓存，删掉只会变慢，不会丢数据 |
